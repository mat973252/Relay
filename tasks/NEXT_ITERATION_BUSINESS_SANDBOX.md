# 持久化报表导出业务沙箱

2026-09-26：用户要求自行构造真实业务流程，不再等待选择第三方服务。本阶段使用合成订单、本机独立 HTTP 进程、独立 SQLite 和 CSV 产物，不执行真实业务写入。

业务契约：POST 接单返回 202，不代表完成；查询副本暂不可见和 pending 均不可证明未执行；只有持久化完成且存在可校验产物才返回 complete；明确拒绝的订单范围可返回 422。业务请求 ID 在重启和新模型会话之间保持稳定。

验收：
1. 202、接单后断线、Relay 在接单后被强制终止，均不得误报完成或自动重复 POST。
2. provider 与 Relay 双进程重启后，原有订单任务仍存在；not_visible、pending 保持 UNKNOWN。
3. worker 生成正确 CSV 和 SHA-256 后，只读 reconcile 才变 CONFIRMED；任务数、产物数和 POST 数均为 1。
4. 明确拒绝不创建任务；两个不同的业务请求不得混淆。
5. 使用 AISIX 真实模型和隔离 Pi 会话，只开放 Relay custom tools，实际执行提交、发现未完成请求与恢复。保留可核验会话和 effect 历史，模型失败单独报告。
6. 运行 Windows 和 Linux Node22/24 的相关回归，报告准确计数与边界。这证明自建沙箱的业务契约，不代表所有第三方 provider、跨主机锁或生产安全。不得使用 Devin。
