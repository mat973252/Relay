## Clock-sensitive wait regression (2026-10-03)

The original failure logged about 281 ms of monotonic test duration while a
five-second `Date.now()` deadline had expired. This is consistent with a wall-clock
jump, but no contemporaneous clock samples exist; the historical root cause is
still unproven.

A deterministic test moves `Date.now()` forward by 60 seconds between reads.
The old wait fails immediately with the same assertion. The wait now uses
`performance.now()` with the same five-second budget. A second regression proves
that reaching the exact monotonic deadline rejects before another poll. The
change affects only the business-sandbox test harness, not effect semantics.

With the two new tests, Ubuntu Node 24.4.1 full `pnpm check` passed 208 tests,
zero skips. Independent review requested a stricter exact-deadline assertion;
after adding it, the seven business-sandbox tests passed on Ubuntu Node 24.4.1
and Windows Node 22.23.3. The Ubuntu crash demo and host-template checks also
passed. This fixes the reproduced clock sensitivity; it does not establish that
all intermittent failures or all test-helper lifecycle issues are eliminated.
